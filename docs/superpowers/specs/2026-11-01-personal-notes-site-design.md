# เว็บบันทึกส่วนตัว — เอกสารออกแบบ

วันที่: 2026-11-01
สถานะ: รออนุมัติ

## 1. เจตนาและเหตุผล

เจ้าของต้องการเว็บไซต์ส่วนตัวสำหรับเก็บบันทึกที่ **เปิดให้ทุกคนอ่านได้**
ปัจจุบันจดบันทึกใน **Samsung Notes บนมือถือ** บันทึกมีทั้ง **ตัวหนังสือพิมพ์และรูปภาพ**
และครอบคลุม **หลายเรื่อง** เว็บต้อง **ฟรีทั้งหมด**

ความสำเร็จ: เจ้าของเขียน/วางบันทึกพร้อมรูปจากมือถือแล้วกดเผยแพร่ได้เอง
โดยไม่ต้องใช้คอมพิวเตอร์ และคนอ่านเปิดดูบนมือถือได้สบาย หาบันทึกตามเรื่องได้

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- หน้าแรกแสดงบันทึกล่าสุดก่อน
- แต่ละบันทึกมีหมวดหมู่ กดดูเฉพาะหมวดได้
- หน้าบันทึกแสดงข้อความและรูปภาพ อ่านง่ายบนมือถือ
- หน้าเขียนบนเว็บ ใช้จากเบราว์เซอร์มือถือได้: วางข้อความ, แนบรูปจากแกลเลอรี, เลือกหมวดหมู่, เผยแพร่
- เฉพาะเจ้าของเท่านั้นที่เขียน/แก้/ลบได้

**ไม่ใช่เป้าหมาย (ตัดออกในรอบนี้)**
- ระบบคอมเมนต์
- ดึงบันทึกจาก Samsung Notes อัตโนมัติ (Samsung Notes ไม่มีช่องทางให้ดึง)
- บันทึกแบบส่วนตัว/ซ่อน
- โดเมนของตัวเอง (ต้องเสียเงิน)

**สิ่งที่ถือว่าล้มเหลวแม้ระบบจะทำงาน**
- ต้องใช้คอมพิวเตอร์ถึงจะเพิ่มบันทึกได้
- มีค่าใช้จ่ายรายเดือน/รายปี หรือเว็บหยุดทำงานเองถ้าไม่ได้ใช้นาน
- รูปจากมือถือ (หลาย MB) ทำให้เว็บโหลดช้า
- คนอื่นนอกจากเจ้าของแก้ไขเนื้อหาได้

## 4. แนวทางที่พิจารณา

| แนวทาง | ข้อดี | ข้อแลก |
|---|---|---|
| **1. เว็บไฟล์ static บน GitHub Pages + หน้าเขียน Sveltia CMS** ✅ เลือก | ฟรีถาวร, ไม่มีฐานข้อมูล, เร็ว, บันทึกเป็นไฟล์ของเจ้าของ | ต้องล็อกอินด้วย GitHub, เผยแพร่แล้วรอ ~1–2 นาที |

## 5. การออกแบบ

### 5.1 ภาพรวม
```
มือถือเจ้าของ ──(เบราว์เซอร์)──> /Claudy/admin/ (Sveltia CMS)
                                     │ commit ไฟล์ .md + รูป
                                     ▼
                          GitHub repo (branch main)
                                     │ GitHub Actions build
                                     ▼
                          GitHub Pages ──> คนอ่าน
```

### 5.2 ตัวสร้างเว็บ — Astro *(การตัดสินใจของผู้ออกแบบ)*
Astro สร้างเว็บ static, รองรับ Markdown content collections และ optimize รูปได้
build และ deploy ด้วย GitHub Actions (`withastro/action`) ทุกครั้งที่มี push เข้า `main`

### 5.3 รูปแบบเนื้อหา
- บันทึก 1 ชิ้น = ไฟล์ Markdown 1 ไฟล์ ใน `src/content/notes/`
- frontmatter:
  - `title` (ข้อความ, บังคับ)
  - `date` (วันเวลา, บังคับ, ค่าเริ่มต้น = ตอนสร้าง)
  - `categories` (รายการข้อความ, อย่างน้อย 1)
  - `cover` (รูป, ไม่บังคับ — ใช้เป็นภาพตัวอย่างในหน้ารายการ)
  - `draft` (true/false, ค่าเริ่มต้น false — ถ้า true จะไม่แสดงบนเว็บ ใช้พักบันทึกที่ยังเขียนไม่เสร็จ)
- เนื้อหา: Markdown แทรกรูปได้หลายรูปในเนื้อ
- รูปเก็บที่ `src/assets/notes/` เพื่อให้ Astro ย่อขนาดและแปลงเป็น WebP ตอน build
- ชื่อไฟล์บันทึก (slug): สร้างจากวันที่ + เลขสุ่มสั้น เพราะชื่อเรื่องภาษาไทยทำ URL ไม่สวย *(การตัดสินใจของผู้ออกแบบ)*

### 5.4 หน้าเว็บฝั่งคนอ่าน
- `/` — รายการบันทึกล่าสุดก่อน (ชื่อเรื่อง, วันที่ภาษาไทย, หมวด, รูป cover ถ้ามี, ข้อความย่อ) แบ่งหน้าละ 20
- `/notes/<slug>/` — บันทึกเต็ม
- `/categories/` — รายชื่อหมวดทั้งหมดพร้อมจำนวนบันทึก
- `/categories/<หมวด>/` — บันทึกเฉพาะหมวด
- `/about/` — หน้าเกี่ยวกับเจ้าของ (แก้จาก CMS ได้)
- 404 ภาษาไทย
- ออกแบบ mobile-first, ฟอนต์ไทย (เช่น Noto Sans Thai / Sarabun), รองรับโหมดมืด
- RSS feed `/rss.xml` *(การตัดสินใจของผู้ออกแบบ — ต้นทุนต่ำ ให้คนติดตามได้)*

### 5.5 หน้าเขียน — Sveltia CMS
- อยู่ที่ `/admin/` (ไฟล์ `public/admin/index.html` + `config.yml`)
- ล็อกอินด้วย **GitHub Personal Access Token** (Sveltia รองรับ) ไม่ต้องตั้ง OAuth server เพิ่ม *(การตัดสินใจของผู้ออกแบบ — ทำให้ฟรีและไม่มีบริการเสริม)*
  - ความปลอดภัย: มีแค่เจ้าของที่มีสิทธิ์เขียน repo จึงไม่มีใครอื่นแก้เนื้อหาได้
- collection `notes` ตามฟิลด์ใน 5.3; `categories` ใช้ช่องเลือกหลายค่าแบบพิมพ์เพิ่มใหม่ได้
- ตั้งค่าย่อรูปฝั่ง CMS ก่อนอัปโหลด (กว้างสุด ~2000px, WebP) เพื่อไม่ให้ repo บวม
- file collection `about` สำหรับหน้าเกี่ยวกับ
- อินเทอร์เฟซ CMS เป็นภาษาไทยถ้า Sveltia รองรับ ไม่งั้นอังกฤษ

### 5.6 คู่มือเจ้าของ
ไฟล์ `README.md` ภาษาไทย อธิบายทีละขั้น:
1. เปิด GitHub Pages (Settings → Pages → Source: GitHub Actions)
2. สร้าง Personal Access Token (fine-grained, เฉพาะ repo นี้, สิทธิ์ Contents: Read and write)
3. เข้า `/admin/` บนมือถือ, ล็อกอิน, เพิ่มลงหน้าจอหลัก
4. ขั้นตอนคัดลอกบันทึกจาก Samsung Notes → วางใน CMS → แนบรูป → เผยแพร่

## 6. การทดสอบ
- build ต้องผ่านโดยไม่มี error (`npm run build`)
- ทดสอบอัตโนมัติ (Vitest) สำหรับ logic: เรียงวันที่, กรอง draft, จัดกลุ่มหมวด, สร้าง slug, จัดรูปแบบวันที่ไทย
- ทดสอบหน้าเว็บด้วย Playwright ที่ความกว้างมือถือ (375px): หน้าแรก, หน้าบันทึก, หน้าหมวด, ไม่มีการเลื่อนแนวนอน
- ตรวจว่า `/admin/` โหลดได้และ config ถูกต้อง

## 7. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ
- สี/ธีม/เลย์เอาต์ละเอียด (ภายใต้ mobile-first, เรียบ อ่านง่าย)
- เวอร์ชันแพ็กเกจ
- โครงสร้าง component ภายใน
- บันทึกตัวอย่าง 2–3 ชิ้นเพื่อให้เว็บไม่ว่างตอนเปิดครั้งแรก (ลบได้)
